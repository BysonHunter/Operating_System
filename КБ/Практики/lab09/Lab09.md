## Подготовка: версия, программы и сеть

Все команды основного эксперимента выполняются **локально в терминале Astra Linux, от обычного учебного пользователя**, в каталоге `~/oslab/lab09`. Kali не выполняет обращений к модели и во время установки пакетов выключена. Администраторские права нужны только для установки пакетов и восстановления сетевой конфигурации.

### Проверка до начала работы

Распакуйте учебный комплект файловым менеджером в `~/oslab/lab09`, чтобы непосредственно в этой папке находились `mac_model.py`, `Lab09.md`, `Варианты.md`, `README.md` и `SHA256SUMS`. Не ограничивайтесь одним текстом задания: программа входит в комплект.

В терминале Astra выполните:

```bash
mkdir -p "$HOME/oslab/lab09"
cd "$HOME/oslab/lab09"
pwd
cat /etc/os-release
if [ -r /etc/astra_version ]; then cat /etc/astra_version; fi
uname -r
command -v python3
python3 --version
python3 -c 'import sys, argparse, csv, datetime, hashlib, json, os; print("MODULES_OK"); sys.exit(0 if sys.version_info >= (3, 5) else 1)'
printf 'python_check_exit=%s\n' "$?"
command -v sha256sum
command -v ip
ip -4 addr show
ip -4 route show
ip -6 route show default
```

**Ожидается:** текущая система идентифицирована, Python не ниже 3.5, строка `MODULES_OK`, `python_check_exit=0`; найдены `sha256sum` и `ip`. Если Python отсутствует, команда проверки модулей не запустится — сначала выполните установку ниже. Если проверка закончилась ненулевым кодом, запуск эксперимента откладывается до устранения причины.

Предоставленный ISO с именем `orel-current.iso` содержит «Орёл» **2.12.22** и штатный Python **3.5.3**. Фактически установленная VM могла быть обновлена или развёрнута из другого образа: в отчёт переносится её собственный вывод, а не версия из имени файла. Модель использует синтаксис Python 3.5 и стандартную библиотеку. Для неё не требуются pip, gcc, PARSEC, auditd, ACL, attr и дополнительные Python-пакеты. Наличие `argparse`, `json`, `csv` и `hashlib` проверяется импортом, а не установкой одноимённых случайных пакетов.

После получения всех файлов:

```bash

python3 mac_model.py --help
```

**Контроль:** контрольные суммы файлов дают `OK`, справка перечисляет `init`, `show`, `suite`, `access`. SHA-256 помогает обнаружить изменение выданного комплекта; сам по себе файл с хешами не удостоверяет автора.

### Установка отсутствующих компонентов

Полный интерпретатор и его стандартные модули устанавливаются пакетом `python3`; APT разрешает зависимости автоматически. Сначала проверьте источник и предлагаемую версию, затем выполните пробное разрешение зависимостей:

Соответствие остальных команд пакетам: `ip` — `iproute2`; `sha256sum`, `cat`, `cp`, `mkdir`, `pwd`, `uname` — `coreutils` (часть команд также имеет встроенную реализацию Bash); оболочка — `bash`; `apt-get`, `apt-cache`, `apt-cdrom` — `apt`. Необязательный `nmcli` принадлежит `network-manager`; устанавливать его вместо действующего сетевого менеджера не требуется. Если отсутствует `ip` или `sha256sum`, после подключения доверенного источника проверьте `apt-cache policy iproute2 coreutils`, выполните пробную команду `sudo apt-get -s install iproute2 coreutils`, затем установите недостающий пакет командой `sudo apt-get install iproute2` или `sudo apt-get install coreutils`. После установки повторите `command -v` и соответствующую входную проверку. Если недоступен сам APT или административный вход, используйте штатный графический менеджер пакетов с учебной административной записью либо восстановите согласованный образ; модель не запускается с пропущенной подготовкой.

```bash
apt-cache policy python3
sudo apt-get -s install python3
```

Если уже установленная система проходит проверку импортов, ничего переустанавливать не нужно. Если APT предлагает удалить важные системные пакеты, заменить выпуск ОС или установить пакеты Special Edition в «Орёл», не подтверждайте операцию. `Candidate: (none)` означает отсутствие подходящего источника в текущей конфигурации APT, а не отсутствие Python в принципе.

**Способ 1: доверенный установочный ISO, без внешней сети.** Он предпочтителен, если действующая политика межсетевого экрана после практической № 8 блокирует DHCP/DNS/выход в Интернет либо старый сетевой репозиторий недоступен. Подключите в виртуальный оптический привод ISO того же выпуска и архитектуры, что и установленная ОС. Для VM, установленной из проверенного «Орла» 2.12.22, исходный ISO содержит пакет python3 3.5.3 и его штатные зависимости. Извлекать отдельные deb вручную не требуется.

sudo apt-get -s install python3
sudo apt-get install python3

Ошибки подписи и несовпадение версий не обходятся отключением проверки подлинности.

<a id="theory"></a>

## Необходимая теория

При дискреционном управлении доступом владелец объекта может в пределах своих полномочий выдавать права другим пользователям. При мандатном управлении решение дополнительно определяется обязательной политикой, которую обычный владелец отменить не может. В защищённой ОС правила применяет доверенный механизм на контролируемых путях доступа. Наличие поля `label` в JSON само по себе такого механизма не создаёт.

В модели метка имеет вид `(h, C)`: h — числовой уровень конфиденциальности, C — множество категорий. Категории представлены битовой маской. Маска 1 обозначает один элемент, 8 — другой, а 9 = 1 | 8 — их объединение. Число 8 больше 1, но множество с маской 8 **не включает** множество с маской 1. Правильная проверка включения: `(C_старшей & C_младшей) == C_младшей`.

Метка X доминирует над Y, если одновременно `hX >= hY` и `CX` включает `CY`. Разрешённый максимум пользователя (`clearance`) ограничивает выбираемую активную метку (`active`). Максимальные полномочия не означают, что они действуют в любой сессии. Предложенная метка выше разрешённого максимума должна отклоняться до проверки объекта.

Используется упрощённая Bell–LaPadula с фиксированными метками объектов и обычными субъектами без обходных привилегий. Она описывает конфиденциальность, а не целостность. В таблице 1 приведены правила, по которым необходимо самостоятельно вычислить результаты.

Таблица 1 — Правила учебной модели

| Операция | Условие разрешения | Смысл потока |
| --- | --- | --- |
| read | активная метка субъекта доминирует над меткой объекта | объект → субъект; запрещено чтение вверх |
| write | метка объекта доминирует над активной меткой субъекта | субъект → объект; запрещена запись вниз |
| readwrite | выполнены оба предыдущих условия | в данной модели нужны равные метки |
| copy | один субъект может прочитать источник и записать приёмник | обе проверки выполняются до изменения приёмника |

`write` здесь означает добавление искусственной строки без предварительного чтения объекта; при `copy` приёмник заменяется содержимым источника. Запись вверх допустима по выбранной модели конфиденциальности, но не доказывает целостность высокоуровневого объекта. Не переносите этот результат автоматически на конкретную операцию PARSEC: файловые контейнеры, дополнительные атрибуты, МКЦ, DAC и привилегии в этой программе не реализованы.

При отказе программа не должна возвращать данные объекта и не должна менять хранилище объектов. Она записывает причину и хеши состояния до/после в `audit.jsonl`. Это **журнал учебной модели**, не журнал ядра, journald или auditd. Его может изменить владелец файла; SHA-256 не делает его доверенным или защищённым от подделки.

## Индивидуальное задание

Выберите [свой вариант из 27](Варианты.md) по номеру в журнале. Варианты различаются уровнем H и масками A/B; низкий уровень `L = H - 1`. Все варианты проверяют одинаковые 16 сценариев и имеют сопоставимую сложность. A и B — различные категории, `A | B` — их объединение.

Создайте четырёх **логических** пользователей: low с активной и максимальной меткой `(L,A)`; high — `(H,A)`; foreign — `(H,B)`; wide — `(H,A|B)`. Дополнительно исследуйте ошибочную проверку категорий на копии программы, подтвердите исправление повторным запуском, покажите отсутствие принудительного контроля вне модели и сформулируйте границы применимости результатов.

## Ход выполнения

План занятия: до 15 минут — готовность ПО и изоляция; 15–25 — метки и теория; 25–40 — собственный прогноз; 40–60 — матрица и журнал; 60–75 — ошибка, повторная проверка и границы модели; 75–90 — доказательства, выводы и восстановление. Если установка требует больше времени, сначала завершите подготовку стенда: непроверенные зависимости и оставшийся NAT нельзя компенсировать пропуском проверки изоляции.

### 1. Зафиксируйте вариант и создайте модель

**Машина/программа/каталог/права:** Astra, Bash и Python, `~/oslab/lab09`, обычный пользователь. В первой строке ниже вместо 7 задайте свой номер. Не меняйте параметры других вариантов в программе.

```bash
cd "$HOME/oslab/lab09"
V=7
NN=$(printf '%02d' "$V")
RUN="run-v$NN"
python3 mac_model.py init --variant "$V" --workspace "$RUN"
python3 mac_model.py show --workspace "$RUN"
```

**Ожидается:** новый каталог с `policy.json`, `objects.json`, пустым `audit.jsonl` и шаблоном `predictions.csv`. `show` выводит логические метки и хеши данных, но не содержимое объектов. Сравните `parameters` с [вариантами](Варианты.md) и вручную раскройте A, B, A|B в двоичном виде. Проверьте, что максимум каждого субъекта включает его активную метку.

Если каталог существует, `init` завершится ошибкой и не затрёт предыдущие данные. Выберите новое имя, например `run2-v07`, и присвойте его переменной RUN; не удаляйте результаты предыдущего опыта ради повторного запуска.

### 2. Выполните расчёт до эксперимента

**Контекст:** тот же каталог и обычный пользователь; текстовый редактор. Откройте `$RUN/predictions.csv`, заполните столбцы `predicted` и `explanation` для T01–T16. Используйте правило доминирования, а не числовое сравнение масок. Для copy проверьте отдельно источник и приёмник; для readwrite — обе операции. Объяснение «так решила программа» не является прогнозом.

После заполнения сохраните файл UTF-8 и зафиксируйте его до запуска:

```bash
sha256sum "$RUN/predictions.csv" > predictions.sha256
```

**Проверка:** 16 непустых прогнозов и объяснений. Хеш подтверждает неизменность зафиксированного файла при дальнейшем сравнении; время и порядок работы дополнительно подтверждаются демонстрацией преподавателю, а не одной контрольной суммой.

### 3. Выполните 16 запросов

**Контекст:** Astra, терминал, обычный пользователь, каталог с `mac_model.py`.

```bash
python3 mac_model.py suite --workspace "$RUN" > suite-output.txt
printf 'suite_exit=%s\n' "$?"
cat suite-output.txt
sha256sum -c predictions.sha256
```

**Ожидается:** код запуска suite равен 0, перечислены 16 решений, созданы `$RUN/results.csv` и 16 строк `$RUN/audit.jsonl`; прогноз не изменён. Код 0 у suite означает завершение серии, а не разрешение всех запросов. Отклонения — обязательная часть эксперимента. Для отдельного `access` используются коды 0 — разрешение, 3 — отказ по политике модели, 2 — ошибка аргументов/формата/файла. Ненулевой код оболочки после deny не является сбоем Astra.

`suite` требует свежую модель с пустым журналом и не перезаписывает результаты. Если до серии выполнялись ручные запросы, создайте новое рабочее пространство, перенесите собственный прогноз и заново зафиксируйте его хеш.

Сопоставьте прогноз и факт. Для каждого расхождения укажите исходную ошибку в рассуждении, правильную проверку и фактическую причину из журнала. Не исправляйте прогноз задним числом: уточнение внесите отдельным столбцом или в отчёт.

### 4. Докажите причину отказов

**Контекст:** обычный пользователь Astra; анализ JSON/CSV в редакторе и терминале. Посмотрите журнал, не применяя `json.tool` ко всему JSONL как к одному JSON-документу:

```bash
python3 -c 'import json,sys; rows=[json.loads(s) for s in open(sys.argv[1],encoding="utf-8")]; print("events=",len(rows)); [print(r["case"],r["allowed"],r["reason"],r["state_before"]==r["state_after"]) for r in rows]' "$RUN/audit.jsonl"
```

**Проверка:** количество событий 16. Для T02, T05, T07, T09, T10, T12, T15 и T16 объясните соответствующую причину; при каждом отказе хеш состояния до и после должен совпасть. Совпадение хеша при разрешённом read также нормально: чтение не меняет объекты.

Изучите T12 отдельно. Копирование требует допуска к источнику и к записи в приёмник. Покажите, какая проверка не прошла и почему запрещённое копирование не должно предварительно обнулить приёмник. Сравните с T13. Для T15 сравните запрошенную метку, максимум и отсутствие доступа; повышение числа в аргументе не создаёт полномочие.

Хеши `state_before`/`state_after` вычисляются над каноническим JSON-представлением всех объектов, а не над байтами файла. Их не следует побайтово сопоставлять с выводом `sha256sum objects.json`: это разные представления данных. В журнал не записывается прочитанное содержимое; тестовые данные записи содержатся в запросе.

### 5. Найдите ошибку проверки категорий и выполните регрессионную проверку

**Контекст:** Astra, текстовый редактор, обычный пользователь. Сохраните исходную программу, создав отдельную учебную копию:

```bash
cp mac_model.py mac_model_faulty.py
```

В функции `read_decision` **только в этой копии** замените правильную строку:

```python
if (active['categories'] & obj['categories']) != obj['categories']:
```

на намеренно неверную:

```python
if active['categories'] < obj['categories']:
```

Не меняйте проверку уровня, write_decision, метки или исходный `mac_model.py`. До запуска запишите, какой запрос должен выявить ошибку и почему более крупное число маски не означает включения категорий.

```bash
python3 mac_model_faulty.py init --variant "$V" --workspace "faulty-v$NN"
python3 mac_model_faulty.py suite --workspace "faulty-v$NN" > faulty-output.txt
cat faulty-output.txt
```

**Ожидается:** выявлено изменение решения в запросе с несовпадающими категориями; в отчёте сравниваются конкретные ID, причины и маски из исходной и ошибочной моделей. Недостаточно написать, что «ошибка найдена»: укажите неразрешённый информационный поток.

Исправьте строку в учебной копии обратно, создайте новую модель и повторите серию:

```bash
python3 mac_model_faulty.py init --variant "$V" --workspace "fixed-v$NN"
python3 mac_model_faulty.py suite --workspace "fixed-v$NN" > fixed-output.txt
```

**Контроль:** восстановлены все 16 решений, включая прежние разрешения. Проверка только одного отказа недостаточна: исправление не должно запретить всё подряд. Сравнивайте решения и причины; хеши политики/состояния и временные отметки могут использоваться как дополнительные признаки, но не заменяют анализ операций.

### 6. Покажите границу модели

**Контекст:** Astra, тот же обычный пользователь Linux, отдельный каталог опыта. Сначала подтвердите отказ модели:

```bash
python3 mac_model.py init --variant "$V" --workspace "boundary-v$NN"
python3 mac_model.py access --workspace "boundary-v$NN" --subject low --op read --object high_note
printf 'access_exit=%s\n' "$?"
```

**Ожидается:** `DENY` выражен полем `allowed=false`, причиной READ_LEVEL и кодом 3; содержимое high_note не напечатано. Затем обойдите **только учебную оболочку**, прочитав свой файл данных обычной программой:

```bash
python3 -c 'import json,sys; data=json.load(open(sys.argv[1],encoding="utf-8")); print(data["high_note"]["data"])' "boundary-v$NN/objects.json"
```

**Ожидается:** синтетическая строка доступна, поскольку текущему пользователю Linux принадлежит хранилище. Чтение вне модели не порождает запись в её журнале. Посчитайте строки журнала этой модели до и после прямого чтения: оно не должно увеличить их число.

Объясните два независимых ограничения: программа доверяет переданному `--subject`, не связывая его с аутентифицированной записью ОС; её решение можно обойти чтением/изменением обычных файлов. Кроме того, последовательные запуски не отслеживают знания человека и не предотвращают перенос уже увиденной строки в новый низкоуровневый запрос. В настоящей системе необходимы защищённая доверенная база, связывание с учётными записями и полнота контроля обращений. Полученный результат не является обходом PARSEC: PARSEC здесь не выполнялся.

### 7. Сохраните результаты и восстановите стенд

**Контекст:** Astra, обычный пользователь; затем хостовый гипервизор при необходимости отката. Сохраните исходную, ошибочную и исправленную серии, прогноз с первоначальным хешем, вывод прямого чтения и собственные выводы. Не перезаписывайте baseline практической № 1.

```bash
ip -4 addr show > network-after.txt
ip -4 route show >> network-after.txt
ip -6 route show default >> network-after.txt
sha256sum mac_model.py "$RUN/predictions.csv" "$RUN/results.csv" "$RUN/audit.jsonl" > evidence.sha256
sha256sum -c evidence.sha256
```

**Ожидается:** контрольные суммы `OK`, сеть снова соответствует паспорту. Все изменения основного опыта ограничены папкой `~/oslab/lab09`; системные пользователи и настройки защиты не изменены. После сохранения отчёта можно удалить именно свои учебные каталоги файловым менеджером. Если применялся снимок для отката, сначала перенесите доказательства в разрешённое хранилище: откат уничтожит изменения внутри VM. Возврат к снимку до установки отменит и установленные пакеты; повторная проверка готовности обязательна.
