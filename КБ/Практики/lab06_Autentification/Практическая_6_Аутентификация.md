## Подготовка: программы, установка и сеть

### Проверка фактического выпуска

**Astra, локальная консоль, Bash, обычный пользователь; sudo — только в указанных командах.** Не начинайте с изменения PAM. Сначала получите:

```bash
cat /etc/os-release
if [ -r /etc/astra_version ]; then cat /etc/astra_version; fi
uname -r
dpkg-query -W libpam0g libpam-modules libpam-modules-bin libpam-runtime libpam-pwquality openssh-server
command -v pam_tally2
command -v passwd
command -v pam-auth-update
sudo find /lib /usr/lib \( -name pam_pwquality.so -o -name pam_tally2.so -o -name pam_succeed_if.so \) -print
sudo /usr/sbin/sshd -t
sudo grep -nE '^[[:space:]]*(@include|auth|account)' /etc/pam.d/sshd
sudo grep -nE 'pam_pwquality|pam_unix' /etc/pam.d/common-password
```

**Ожидается:** найдены `pam_tally2.so`, утилита `pam_tally2`, `pam_succeed_if.so` и `pam_pwquality.so`; `sshd -t` завершился без ошибки. В выданном ISO «Орёл» 2.12.22 содержатся libpam-modules/libpam-modules-bin/libpam-runtime 1.1.8-3.6, libpam-pwquality 1.3.0-1.astra2 и openssh-server 7.4p1-10+deb9u6astra6. Установленные версии фиксируйте по собственному выводу: наличие пакета на ISO не означает его установку в VM.

Для этого выпуска используются **pam_tally2 и отдельный файл счётчиков**. `pam_faillock`, его режимы preauth/authfail/authsucc, утилита faillock и окно fail_interval не являются средствами данного задания. Их не нужно устанавливать из пакетов Kali, Debian другого выпуска или Astra SE.

**Профиль совместимости:** локальная UNIX-запись; в SSH PAM-файле по одному `@include common-auth` и `@include common-account`; отсутствие уже действующей конкурирующей блокировки. Прочитайте `common-auth` и `common-account`, а также весь `/etc/pam.d/sshd`. Если есть ALD/LDAP, собственный путь аутентификации, дополнительные предварительные auth-правила, другая схема включений или существующий pam_tally/pam_tally2/pam_faillock, не накладывайте второй счётчик: сначала преподаватель адаптирует профиль. Штатные строки безопасности не удаляются.

На Kali выполните `ssh -V` и `dpkg-query -W openssh-client`. Клиент должен быть доступен. Для Astra в команды включён полный путь `/usr/sbin/sshd`: отсутствие sshd в PATH обычного пользователя не доказывает отсутствия серверного пакета.

### Установка недостающих пакетов

На Astra модуль качества находится в `libpam-pwquality`; модуль tally2 — в `libpam-modules`; его утилита — в `libpam-modules-bin`; `pam-auth-update` — в `libpam-runtime`; сервер SSH — в `openssh-server`. APT устанавливает зависимости автоматически, включая libpwquality и словарные библиотеки. gcc, pip, Hydra и sshpass не нужны.

Сначала определите источник пакетов:

```bash
apt-cache policy openssh-server libpam-pwquality libpam-modules libpam-modules-bin libpam-runtime
sudo apt-get -s install openssh-server libpam-pwquality libpam-modules libpam-modules-bin libpam-runtime
```

`Candidate: (none)` означает, что подходящий источник не настроен. Если симуляция предлагает несовместимую замену PAM, удаление системных пакетов или смену выпуска, установку не подтверждайте.

**Установка без внешней сети:** подключите доверенный ISO того же выпуска и архитектуры в виртуальный оптический привод. Для неизменённой установки «Орёл» 2.12.22 подходит исходный ISO 2.12.22. Зарегистрируйте его:

```bash
sudo apt-cdrom add
apt-cache policy openssh-server libpam-pwquality libpam-modules libpam-modules-bin libpam-runtime
sudo apt-get -s install openssh-server libpam-pwquality libpam-modules libpam-modules-bin libpam-runtime
sudo apt-get install openssh-server libpam-pwquality libpam-modules libpam-modules-bin libpam-runtime
```

Используйте этот способ и при блокировании доступа к репозиторию действующей политикой firewall после практической № 8. Не сбрасывайте firewall ради установки. Для обновлённой VM нужен источник её фактического выпуска, а не принудительное понижение пакетов до версии старого ISO.

**Временная установка через NAT разрешена только на этапе подготовки:**

1. Сохраните параметры текущего подключения: имя интерфейса, MAC, сеть гипервизора, IPv4/IPv6, маршруты, шлюз и DNS; снимки вкладок действующего сетевого профиля. Запишите `ip -4 addr show`, `ip -4 route show` и `ip -6 route show`. Kali на это время выключите. Создайте проверенный снимок выключенной Astra до установки.
2. На выключенной Astra замените режим **того же единственного адаптера** с Internal Network на NAT. Второй адаптер и Bridged не добавляйте.
3. После запуска в штатном редакторе подключения выберите IPv4 «Автоматически (DHCP)», уберите из временного профиля статические адреса, маршруты, ручные шлюз и DNS. Если редактор позволяет, сохраните исходный профиль и создайте временный NAT-профиль без автоподключения. Переподключите интерфейс.
4. Проверьте выдачу адреса и появление NAT default route командами `ip -4 addr show` и `ip -4 route show`. Адрес выдаёт DHCP, заранее его не назначайте. Используйте только согласованный репозиторий установленного выпуска CE; затем `sudo apt-get update`, повторный `apt-cache policy`, симуляция установки и команда установки выше. Не выполняйте upgrade/dist-upgrade и не отключайте проверку подписи. При ошибках старого репозитория используйте ISO.
5. После проверки пакетов выключите Astra, верните Internal Network `oslab-vNN`. В гостевой ОС восстановите исходный профиль: **Astra `10.50.V.10/24`, без шлюза и DNS**, прежние маршруты и IPv6 по паспорту. Удалите временный профиль либо отключите его автоподключение. Kali верните в ту же сеть с `10.50.V.20/24`.
6. Проверьте адреса и отсутствие внешнего маршрута: `ip -4 route show default` и `ip -6 route show default` не должны показывать default route. Сверьте также имя Internal Network в гипервизоре. Внешние адреса для доказательства изоляции не опрашиваются. При неудачной установке возврат сети всё равно обязателен.

Установку и подготовку образа желательно завершить до 90-минутного занятия. После установки повторите входную проверку модулей. До изменения PAM/SSH дополнительно создайте и проверьте исходный снимок `pre-lab06-VNN` **выключенной VM**. Запись должна присутствовать в списке снимков; незавершённый live snapshot и индикатор прогресса точкой восстановления не считаются.

## Цель и задачи

**Цель:** настроить проверку качества нового пароля и временную блокировку учебной записи при SSH-аутентификации, подтвердить результат счётчиком, журналом и контрольными входами, затем восстановить систему.

**Задачи:** определить фактическую версию и PAM-стек; подготовить зависимости и резервирование; создать временную локальную запись; выполнить три отрицательных и один положительный парольный тест; проверить сброс счётчика после успешного входа, отказ при превышении порога, восстановление по времени и вручную; объяснить управление PAM и сохранить доказательства.

## Необходимая теория

PAM разделяет обработку на auth (аутентификация), account (допуск записи), password (смена пароля) и session (создание сеанса). В `/etc/pam.d/*` обычная строка имеет поля `type control module-path arguments`. `required` сохраняет ошибку до завершения стека, `requisite` прекращает обработку при ошибке, `sufficient` может завершить стек успехом, если до этого нет обязательной ошибки. Расширенное управление `success=1` пропускает следующую строку при успешном результате.

В этой работе существующий `common-auth` сохраняется и вызывается один раз. Дополнительный tally2 выполняется перед ним только для учебного пользователя. Его обязательная ошибка не отменяется правильным UNIX-паролем, проверенным дальше по стеку. Отдельное правило account сбрасывает счётчик после успешной аутентификации в подготовленном профиле. Синтаксис `substack` здесь не нужен: это самостоятельный вид поля control, а не модуль после скобочного control.

`pam_pwquality` проверяет **новый пароль при смене**, а не качество уже установленного пароля при каждом входе. Нулевые dcredit/ucredit/lcredit/ocredit исключают бонусы длины за классы; minclass задаёт число классов, maxrepeat — допустимое число одинаковых символов подряд. Словарные и другие проверки также могут отклонить кандидат. enforce_for_root нужен для испытаний через `sudo passwd`.

`pam_tally2` увеличивает счётчик при вызове auth **до проверки пароля**. При последующем успешном входе счётчик сбрасывается. Поэтому число в утилите — не всегда число введённых неверных паролей: отклонённая из-за блокировки попытка с правильным паролем также увеличивает его.

Для `deny=D` проверяется **tally > D**. После D подряд неверных входов следующая попытка, увеличив tally до D+1, будет отвергнута даже с правильным паролем, если таймаут ещё не истёк. Не заменяйте условие на предположение «модуль блокирует при tally >= D».

`unlock_time=U` разрешает следующую аутентификацию после достаточного перерыва с предыдущей учитываемой попытки. Фоновый таймер не обязан обнулять число в файле. В данном опыте отсчитывайте ожидание **после завершения последней отклонённой попытки D**, не только после последнего неверного пароля серии C. Дополнительные попытки во время ожидания меняют временную отметку и могут отодвинуть восстановление. После успешного входа сброс подтверждается отдельно.

У tally2 нет параметра fail_interval и скользящего окна учёта неудач. Ручной просмотр счётчика без `--reset` не является попыткой входа и не должен изменять его. Для опыта используется отдельный файл, чтобы не затрагивать счётчики других служб. Счётчик и системный журнал — разные доказательства: одно сообщение клиента «Permission denied» не объясняет причину отказа.

### 1. Сохраните исходное состояние

**Astra, локальная консоль, Bash; административный сеанс остаётся открытым.** Задайте V, проверьте существование снимка и выполните:

```bash
V=1
printf -v NN '%02d' "$V"
U_NAME="lab06$NN"
WORK="$HOME/oslab/lab06-V$NN"
BACKUP="/root/lab06-backup-V$NN-$(date +%Y%m%d-%H%M%S)"
TALLY="/var/log/lab06-tally-V$NN"
mkdir -p "$WORK"
sudo mkdir -m 700 "$BACKUP"
sudo cp -a /etc/pam.d "$BACKUP/pam.d"
sudo cp -a /etc/ssh/sshd_config "$BACKUP/sshd_config"
if [ -d /etc/ssh/sshd_config.d ]; then
    sudo cp -a /etc/ssh/sshd_config.d "$BACKUP/sshd_config.d"
fi
sudo ls -ld "$BACKUP" "$BACKUP/pam.d"
getent passwd "$U_NAME"
sudo test -e "$TALLY"
printf 'counter_exists_exit=%s\n' "$?"
```

**Проверка:** копии существуют; каталог резервной копии новый. Любая ошибка mkdir/cp останавливает подготовку до выяснения причины. Для нового пользователя getent не должен вернуть запись; `counter_exists_exit=1` означает, что отдельного файла ещё нет. Если пользователь или файл уже существуют, их не затирают: сначала выясняют происхождение либо возвращаются к чистому снимку. Повторный запуск не должен подменять резервную копию исходного состояния уже изменёнными файлами.

### 2. Создайте локальную учебную запись и проверьте SSH

**Astra, консоль, sudo только для создания записи и управления службой:**

```bash
sudo useradd -m -s /bin/bash "$U_NAME"
sudo passwd "$U_NAME"
sudo chage -l "$U_NAME"
sudo systemctl status ssh --no-pager
```

Назначьте уникальный искусственный учебный пароль. Срок записи/пароля не должен требовать смены при первом входе. В sudo и административные группы пользователя не добавляйте. Если сервер установлен, но не запущен, выполните `sudo systemctl start ssh` и повторите status. Проверяйте только интерфейс своей Internal Network. Не меняйте правила firewall автоматически: после практической № 8 доступ TCP/22 с собственной Kali должен быть предусмотрен согласованной политикой.

На **Kali, обычный пользователь**, задайте реальные адрес и имя:

```bash
ASTRA_IP='10.50.1.10'
LAB_USER='lab0601'
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password \
    -o NumberOfPasswordPrompts=1 -o ControlMaster=no -o ControlPath=none \
    "$LAB_USER@$ASTRA_IP"
```

Замените 1/01 своим вариантом. При первом входе сверьте ключ сервера с локальной консолью Astra: `sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`, если клиенту предложен именно этот тип ключа. Проверку host key не отключайте. После успешного входа выполните `id`, затем `exit`. Если парольный вход исходно не работает, эксперимент с ошибками ещё не начинается.

### 3. Настройте качество нового пароля

**Astra, консоль, sudo.** Если pwquality ещё не включён, используйте `sudo pam-auth-update`, выбрав профиль Pwquality. Остальные действующие защитные профили сохраняются. Если объявлен конфликт профилей cracklib/pwquality, переход на профиль pwquality выполняет преподаватель; проверку качества не отключают. После сохранения убедитесь, что pwquality вызывается один раз перед pam_unix, а pam_unix сохраняет параметры своей редакции и `use_authtok`.

В существующей строке `/etc/pam.d/common-password` задайте L/C/R своего варианта, устранив конфликтующие дубли параметров. Для варианта 1:

```text
password requisite pam_pwquality.so retry=1 minlen=12 minclass=3 maxrepeat=2 dcredit=0 ucredit=0 lcredit=0 ocredit=0 enforce_for_root
```

Не заменяйте весь common-password. Изменение этой общей строки влияет на смену паролей других локальных записей; в эксперименте меняется только новый учебный пользователь, а затем выполняется восстановление.

Четыре раза отдельно вызовите `sudo passwd "$U_NAME"`: кандидат короче L; кандидат с C−1 классами; кандидат с R+1 одинаковыми символами подряд; допустимый кандидат длиной не менее L+4 с четырьмя классами, без длинных повторов, словарных слов и простых последовательностей. В отрицательных тестах остальные свойства должны удовлетворять требованиям, насколько это допускает словарная проверка. Используйте ASCII. Сохраняйте свойства кандидатов и точное сообщение, но не пароли.

**Ожидается:** три отказа с понятной причиной и принятие последнего кандидата. При retry=1 отказ завершает текущую смену, сохраняя прежний пароль. Если отказ вызван иной проверкой, укажите реальную причину и измените кандидат. Новый принятый пароль используется далее для SSH.

### 4. Подключите счётчик только к учебному SSH-пользователю

**Astra, консоль, редактор PAM с sudo.** Задайте D/U своего варианта; пример:

```bash
D=3
U=60
sudo /usr/sbin/sshd -t
```

В `/etc/pam.d/sshd` перед **единственной существующей** строкой `@include common-auth` вставьте две строки. Сам include сохраните. Для варианта 1 итоговый фрагмент:

```text
auth [success=1 default=ignore] pam_succeed_if.so user != lab0601 quiet
auth required pam_tally2.so file=/var/log/lab06-tally-V01 deny=3 unlock_time=60 onerr=fail
@include common-auth
```

После **существующей** строки `@include common-account` вставьте ещё две строки:

```text
@include common-account
account [success=1 default=ignore] pam_succeed_if.so user != lab0601 quiet
account required pam_tally2.so file=/var/log/lab06-tally-V01 onerr=fail
```

В обоих фрагментах замените имя, путь, D и U своим вариантом; в PAM-файле переменные Bash не подставляются. `file=` должен совпадать с переменной TALLY и во всех командах утилиты. Не переносите D/U в account-строку: там выполняется сброс, а не проверка порога. Существующие account, password и session, включая pam_nologin и другие штатные модули, сохраняются.

**Логика:** для постороннего пользователя условие `user != lab06NN` успешно и пропускает одну следующую строку tally2; затем действует исходный common-стек. Для учебного пользователя условие ложно, tally2 выполняется. `required` сохраняет отказ, но common-auth всё равно проверяет пароль один раз. Правильный пароль не отменяет обязательный отказ tally2. После успешной аутентификации account-правило сбрасывает счётчик. Не применяются even_deny_root, magic_root и глобальное редактирование common-auth.

**Проверка:** сопоставьте новый SSH PAM-файл с резервной копией; число common-auth/common-account осталось по одному; добавлены ровно две пары правил, относящиеся только к lab06NN. Проверьте путь файла и модуль на диске. `sshd -t` **не проверяет корректность PAM**, поэтому обязательны дальнейшие контрольные входы и работающая консоль восстановления.

### 5. Проверьте эффективные параметры SSH и исходный счётчик

**Astra, консоль:**

```bash
KALI_IP='10.50.1.20'
sudo /usr/sbin/sshd -t
sudo /usr/sbin/sshd -T -C "user=$U_NAME,addr=$KALI_IP,host=$KALI_IP" \
  | grep -E 'usepam|usedns|passwordauthentication|permitemptypasswords|authenticationmethods|maxauthtries|allowusers|allowgroups'
```

Замените адрес. Для стандартного профиля без правил Match Host с обратным DNS указан IP клиента; если есть зависимость от имени/UseDNS, преподаватель проверяет реальный сопоставляемый host отдельно. Нужны `UsePAM yes`, `PasswordAuthentication yes`, `PermitEmptyPasswords no`, отсутствие требования второго метода для учебной записи и разрешение пользователя правилами AllowUsers/AllowGroups и account. При необходимости исключение для учебного пользователя и адреса добавляется **в основной `/etc/ssh/sshd_config`**, с проверкой `sshd -t/-T`; OpenSSH 7.4 не следует настраивать через не подключённый каталог sshd_config.d. UsePAM — глобальная настройка, внутри Match её не помещают. Ограничения остальных пользователей не ослабляются.

Если изменялся SSH config, после успешной проверки выполните `sudo systemctl reload ssh`. Только изменение PAM не требует перезагрузки sshd.

```bash
sudo pam_tally2 --file "$TALLY" --user "$U_NAME" --reset
sudo pam_tally2 --file "$TALLY" --user "$U_NAME"
date --iso-8601=seconds | tee "$WORK/test-start.txt"
```

**Ожидается:** счётчик равен 0; файл может быть создан PAM/утилитой автоматически. Не обнуляйте общий tallylog и не сбрасывайте всех пользователей. После ручного reset выполните один правильный SSH-вход из Kali, `id`, `exit`, затем проверьте 0. Если исходный вход не работает, дальнейшие неверные попытки прекращаются до анализа причины.

### 6. Выполните серию A–F

**Kali:** та же команда SSH с одним парольным запросом, только ручной ввод. Параметры ControlMaster/ControlPath исключают повторное использование уже аутентифицированного соединения: каждый тест должен создавать новый обмен. **Astra:** открытая локальная консоль, просмотр `sudo pam_tally2 --file "$TALLY" --user "$U_NAME"` и времени после каждого события. Сохраните промежуточный вывод отдельно. Одна попытка — один фактический парольный обмен; сетевой отказ до запроса пароля не считается.

Порядок и ожидаемые результаты приведены в таблице 4. Между соседними входами серии C и пробой D не делайте пауз, сопоставимых с U; посторонних обращений к записи быть не должно.

Таблица 4 — Контрольные входы и восстановление

| Шаг | Действие на Kali | Контроль на Astra | Ожидание |
| --- | --- | --- | --- |
| A | Один неверный пароль | Счётчик и журнал | tally=1 |
| B | Один правильный вход, затем exit | Счётчик после установленного сеанса | Вход успешен, tally=0 |
| C1…CD | D отдельных неверных входов | Сохранить каждый счётчик и время | 1…D; каждый пароль неверен |
| D | Сразу один правильный пароль | Сохранить счётчик, журнал и время окончания | Вход отклонён; tally=D+1 |
| E | После U+5 секунд **от окончания D**, без новых попыток, один правильный вход | Проверить счётчик после входа/exit | Доступ восстановлен, tally=0 |
| F1 | Повторить D отдельных неверных входов | Сохранить 1…D | Готова новая проверка блокировки |
| F2 | Один правильный пароль сразу | Счётчик и время окончания | Отказ, tally=D+1 |
| F3 | Из локальной консоли сбросить только эту запись | Сохранить вывод reset и 0 | Ручной сброс выполнен |
| F4 | Сразу правильный вход **до истечения U после F2** | Время, успех, счётчик | Доступ восстановлен вручную, tally=0 |

Для F3 используется:

```bash
sudo pam_tally2 --file "$TALLY" --user "$U_NAME" --reset
sudo pam_tally2 --file "$TALLY" --user "$U_NAME"
```

Для E зафиксируйте окончание D временем Astra (`date --iso-8601=seconds`), выждите U+5 секунд и не делайте попыток между ними. Просмотр счётчика не сбрасывает его. Само ожидание не обязано обнулить число: требуются успешный вход и account-сброс. Перезагрузка VM между D и E недопустима как способ разблокировки.

Для F сохраните доказательство, что F4 завершился раньше U относительно F2: иначе успех нельзя уверенно приписать ручному reset, а не таймауту. Вся серия содержит **2D+1 неверных паролей**, максимум 11, и две отклонённые попытки с верным паролем. При неожиданном счётчике или повторных запросах остановитесь; не продолжайте накапливать попытки. MaxAuthTries ограничивает обмены внутри соединения и не заменяет счётчик записи.

### 7. Сопоставьте журнал и счётчики

**Astra, консоль, каталог WORK; sudo — для чтения событий:**

```bash
START=$(cat "$WORK/test-start.txt")
sudo journalctl -u ssh --since "$START" --no-pager > "$WORK/ssh-journal.txt"
sudo journalctl --since "$START" --no-pager \
  | grep -E "sshd|pam_tally2|$U_NAME" > "$WORK/auth-events.txt"
sudo pam_tally2 --file "$TALLY" --user "$U_NAME" > "$WORK/tally-final.txt"
sudo cp /etc/pam.d/sshd "$WORK/pam-sshd.txt"
sudo grep -nE 'pam_pwquality|pam_unix' /etc/pam.d/common-password > "$WORK/password-policy.txt"
sudo /usr/sbin/sshd -T -C "user=$U_NAME,addr=$KALI_IP,host=$KALI_IP" \
  > "$WORK/sshd-effective.txt"
```

Если unit называется иначе, используйте фактическое имя службы. Если записи уходят в `/var/log/auth.log`, сохраните относящиеся к периоду эксперимента строки с учебным пользователем. Зафиксируйте часы обоих узлов; для расчёта U опирайтесь на один источник времени Astra. Парольный отказ клиента без счётчика и серверного события не доказывает блокировку.

Не пытайтесь просматривать бинарный файл tally текстовой командой cat. Приложите читаемые промежуточные выводы утилиты после A, B, каждого C, D, E и F, а не только финальный 0.

### 8. Восстановите систему

Сначала сохраните доказательства **вне откатываемого диска** разрешённым способом. Проверьте их доступность. Затем восстановите проверенный снимок `pre-lab06-VNN`; он возвращает PAM, SSH, пакеты, пользователей и файлы счётчиков к исходному состоянию.

После запуска подтвердите исходный административный вход, отсутствие lab06NN и отдельного tally-файла, если их до опыта не было, исходную SSH/PAM-конфигурацию и изолированную сеть. Не закрывайте единственную рабочую консоль до проверки восстановления. При аварии используется консоль/снимок; глобальное выключение PAM и ручная замена библиотек не являются восстановлением.
