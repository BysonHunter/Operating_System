# Практическая работа №8. Межсетевое экранирование и повторная проверка

**Дисциплина:** Операционные системы. **Специальность:** 10.05.01 «Компьютерная безопасность», университет, 3-й курс. **Продолжительность:** 90 минут; установка пакетов и подготовка снимка выполняются до начала основного занятия. **Оценка:** до 5 баллов.

Тема соответствует практической №8 РПД: минимальная политика nftables/iptables на Astra Linux, повторная проверка из Kali Linux и документирование сокращения доступной сетевой поверхности. В этой работе выбран **nftables**. Предшествующая практическая №7 даёт сведения о службах и портах; работа №8 проверяет изменение их доступности после фильтрации.

<a id="goal"></a>
## 1. Цель и задачи

**Цель:** настроить обоснованную политику входящего трафика учебного интерфейса Astra Linux и доказать её действие сопоставлением сетевых проверок, состояния служб и счётчиков правил.

**Задачи:** проверить готовность двух ОС; получить исходное состояние трёх учебных служб; сформировать правила своего варианта; проверить синтаксис и применить правила с возможностью восстановления; повторить те же проверки; отличить фильтрацию от остановки службы; удалить учебные изменения и подтвердить восстановление.

Результат должен показывать причинную связь «требование → правило → проверка → наблюдение → вывод». Одного снимка вывода Nmap недостаточно. Работа развивает ОПК-12.1 и ОПК-12.2 в части диагностики, защищённого администрирования и восстановления ОС.

## 3. Предварительная подготовка ОС

### 3.1. Зафиксировать версию и полномочия — обе ВМ

**Где:** консоль каждой ВМ, обычный пользователь с правом `sudo`. В домашнем каталоге:

```bash
mkdir -p "$HOME/pr8/results"
cd "$HOME/pr8"
cat /etc/os-release | tee results/os-release.txt
uname -r | tee results/kernel.txt
dpkg --print-architecture | tee results/architecture.txt
sudo -v
ip -br address
ip route
```

Запишите редакцию и версию Astra Linux, выпуск Kali, ядра и архитектуры. Если `sudo` отсутствует, войдите в консоль под выданной административной записью и выполните команды установки без `sudo`. Настройку административного доступа выполните до эксперимента; случайное добавление пользователя в группы эту подготовку не заменяет.

### 3.2. Установка при доступном штатном репозитории

Установка выполняется **до изоляции эксперимента**. Если ВМ уже изолированы, используйте раздел 3.3. Разрешённый временный доступ к репозиторию организуется в режиме подготовки, а затем внешний адаптер отключается. Во время проверок из Kali остаётся только внутренняя учебная сеть.

**На Astra Linux:** используйте репозиторий именно установленной редакции, версии и архитектуры. Не добавляйте источники Debian, Ubuntu или Kali. Проверьте существующие `.list` и `.sources` в `/etc/apt/`; не заменяйте весь список найденной в интернете строкой.

```bash
sudo apt-get update
apt-cache policy nftables iproute2 python3 curl iputils-ping systemd iptables
sudo apt-get -s install nftables iproute2 python3 curl iputils-ping systemd iptables sudo coreutils bash
sudo apt-get install nftables iproute2 python3 curl iputils-ping systemd iptables sudo coreutils bash
```

**На Kali Linux:** используйте действующую ветку собственного официального репозитория. Конфигурация может находиться в `/etc/apt/sources.list` или `/etc/apt/sources.list.d/kali.sources`; не создавайте дублирующие записи и не переносите репозитории Astra.

```bash
sudo apt-get update
apt-cache policy nmap curl python3 iproute2 iputils-ping
sudo apt-get -s install nmap curl python3 iproute2 iputils-ping sudo coreutils bash
sudo apt-get install nmap curl python3 iproute2 iputils-ping sudo coreutils bash
```

Если требуется распаковка архива в ВМ: `sudo apt-get install unzip` на соответствующей машине. APT сам разрешает зависимости; отдельный список имён библиотек вручную составлять не нужно. **Сначала изучите пробную установку `-s`**: при предложении удалить компоненты защиты, рабочую среду или выполнить несогласованное обновление выпуска прекратите установку и восстановите корректный источник пакетов. Полное обновление ОС для этой работы не требуется.

Успех — все нужные пакеты установлены, команды запускаются. Сообщения `Unable to locate package`, `Candidate: (none)` или ошибки подписи означают незавершённую подготовку; не обходите проверку подписи параметром `--allow-unauthenticated`.

### 3.3. Подготовка полностью закрытого стенда

Предпочтительный способ — готовый образ ВМ со всеми пакетами из таблицы 1 и контрольным снимком. Другие допустимые способы:

**A. Установочный/репозиторный ISO той же ОС.** Подключите подходящий носитель к ВМ. Для носителя с поддержкой APT CD-ROM используйте `sudo apt-cdrom add`, затем `sudo apt-get update` и команды установки из раздела 3.2. Используйте именно носитель установленного выпуска и архитектуры. Один ISO может не содержать всех пакетов и зависимостей; это проверяется фактической установкой, а не наличием файла ISO. Для носителя с иным форматом репозитория используйте инструкцию к этому выпуску Astra Linux.

**Б. Подготовленный комплект DEB.** На отдельной подготовительной ВМ, являющейся клоном исходного снимка **целевой** машины, с теми же репозиториями, версией и архитектурой выполните:

```bash
mkdir -p "$HOME/pr8-offline/partial"
sudo apt-get update
```

Затем на клоне Astra:

```bash
sudo apt-get -o Dir::Cache::archives="$HOME/pr8-offline/" --download-only install \
  nftables iproute2 python3 curl iputils-ping systemd iptables sudo coreutils bash
```

На отдельном клоне Kali:

```bash
sudo apt-get -o Dir::Cache::archives="$HOME/pr8-offline/" --download-only install \
  nmap curl python3 iproute2 iputils-ping sudo coreutils bash
```

Не смешивайте эти два комплекта. Если нужен `unzip`, включите его в соответствующий запрос. APT скачивает необходимые для данного исходного состояния зависимости. Загрузка на произвольном компьютере с уже установленными библиотеками **не гарантирует** комплектность для другой ВМ. При отсутствии DEB проверьте: возможно, все требуемые пакеты уже установлены в исходном снимке.

При наличии DEB сохраните рядом их контрольные суммы: в каталоге `pr8-offline` выполните `sha256sum ./*.deb > SHA256SUMS`. Перенесите каталог разрешённым носителем. На соответствующей целевой ВМ, находясь в этом каталоге:

```bash
sha256sum -c SHA256SUMS
sudo apt-get --simulate --no-download install "$PWD"/*.deb
sudo apt-get --no-download install "$PWD"/*.deb
```

Успех — установка без обращения к сети и без неудовлетворённых зависимостей. Если зависимость отсутствует, дополните комплект на идентичном клоне; не используйте цепочку `dpkg -i` и сетевого `apt -f install` как обещание автономной установки. Контрольные суммы проверяют сохранность переноса, а происхождение обеспечивается получением пакетов через доверенный APT на подготовительном клоне.

### 3.4. Контроль готовности

**На Astra Linux:**

```bash
for c in nft ip ss python3 curl ping systemctl systemd-run iptables-save ip6tables-save; do
    command -v "$c" || echo "НЕТ КОМАНДЫ: $c"
done
nft --version
python3 --version
systemctl --version
python3 -c 'from http.server import HTTPServer; from socketserver import ThreadingMixIn; import socket, threading, argparse, ipaddress; print("Python: OK")'
sudo nft list ruleset
```

**На Kali Linux:**

```bash
for c in nmap curl python3 ip ping; do
    command -v "$c" || echo "НЕТ КОМАНДЫ: $c"
done
nmap --version
curl --version
python3 -c 'import socket, argparse, ipaddress; print("Python: OK")'
```

`nft list ruleset` должен завершиться без ошибки. `Operation not permitted` требует проверки административных прав, а не переустановки пакета. Ошибка поддержки семейства/ядра требует совместимого образа Astra Linux. Наличие команды `nft` отдельно от работоспособного `nf_tables` недостаточно. Автоматическое переключение на `iptables-legacy` в этой работе не выполняется.

**Подготовка считается законченной**, когда доступны команды, открываются скрипты, есть консоль и снимок, ВМ видят друг друга во внутренней сети, внешний доступ на время эксперимента отключён. Если действующая защита уже блокирует исходные учебные порты, нужен согласованный учебный образ/снимок, где такие исходные проверки разрешены. Не отключайте защиту всей ОС ради получения желаемого результата.

## 4. Краткая теория

Служба создаёт слушающий сокет. Межсетевой экран определяет, какие пакеты достигнут этого сокета. Поэтому недоступность порта извне не доказывает остановку процесса. Анализ сочетает `ss`, прикладной запрос, внешний scan и счётчики правил.

В nftables таблица объединяет цепочки. Базовая цепочка привязана к сетевому hook; обычная вызывается через `jump`. Здесь таблица `inet` охватывает IPv4 и IPv6, базовая цепочка подключена к `input`, а учебная фильтрация включается только для `iifname` внутреннего интерфейса. `forward` и `output` не изменяются: работа посвящена защите самой Astra Linux, а не маршрутизатора.

В цепочке учебного интерфейса разрешаются только заданный источник Kali, адрес Astra, один TCP-порт, UDP по варианту и диагностический ICMP echo-request. Завершающее правило отбрасывает остальное. Для разрешённого TCP учитываются состояния `new` и `established`; безусловного разрешения всех установленных соединений здесь нет. Политика намеренно узкая, а не универсальная конфигурация серверной ОС.

`accept` в одной базовой цепочке не отменяет возможный запрет в другой. Штатные правила могут ограничивать связь дополнительно. `drop` означает молчаливое отбрасывание: Nmap может показать `filtered` для TCP и `open|filtered` для UDP. `closed` обычно означает отсутствие слушателя/ответ об отсутствии порта. Состояние Nmap описывает наблюдение с конкретного узла, а не вечное свойство службы.

Наличие `inet` не означает, что правила `ip saddr` разрешают IPv6. В этой работе на учебном интерфейсе IPv6 также попадает в завершающий запрет. Это нужно явно отразить в отчёте. Настройка допустимого IPv6-трафика и полноценной сетевой инфраструктуры не входит в этот сценарий.

## 6. Ход выполнения

### Шаг 1. Задать параметры и сохранить исходное состояние — 10 минут

**Где:** обе ВМ, Bash, обычный пользователь. Скопируйте комплект в `$HOME/pr8`, чтобы файлы были доступны как `$HOME/pr8/tools/*.py`. На **каждой** ВМ задайте свой номер и реальные адреса. Угловые скобки ниже — места замены, их нельзя оставлять в команде:

```bash
export N=1
export ASTRA_IP='<IPv4 Astra из паспорта>'
export KALI_IP='<IPv4 Kali из паспорта>'
export PORT_A=$((18000 + 10 * N))
export PORT_B=$((PORT_A + 1))
export PORT_UDP=$((PORT_A + 2))
export TABLE="pr8_$N"
mkdir -p "$HOME/pr8/results"
cd "$HOME/pr8"
printf 'N=%s Astra=%s Kali=%s A=%s B=%s UDP=%s\n' \
  "$N" "$ASTRA_IP" "$KALI_IP" "$PORT_A" "$PORT_B" "$PORT_UDP"
```

Замените `N=1` своим номером. Переменные действуют только в текущей оболочке: в новом терминале выполните этот блок снова. После ввода проверьте, что он не содержит `<...>`. На каждой ВМ проверьте `test -f tools/lab_services.py` и `test -f tools/udp_probe.py`; отсутствие сообщения при коде 0 означает, что файлы найдены. На Astra дополнительно:

```bash
export LAB_IF='<имя внутреннего интерфейса Astra>'
ip -br address
ip route get "$KALI_IP"
sudo nft list ruleset > results/nft-before.txt
sudo iptables-save > results/iptables-before.txt
sudo ip6tables-save > results/ip6tables-before.txt
systemctl is-active nftables ufw firewalld
```

Код возврата последней команды может быть ненулевым, если часть служб отсутствует/неактивна; это не сбой всего задания. Зафиксируйте активных управляющих firewall средств. Не запускайте параллельно изменение политики через Fly, UFW, firewalld или `iptables`. Не выполняйте `nft flush ruleset`, `iptables -F`, смену alternatives или отключение штатной защиты.

**Ожидание и проверка:** маршрут к Kali использует `$LAB_IF` и `$ASTRA_IP`, интерфейс относится к внутренней сети. На Kali команда `ip route get "$ASTRA_IP"` также указывает внутреннюю сеть. Если маршрут идёт через внешний шлюз, исправьте конфигурацию стенда до сетевых тестов.

### Шаг 2. Запустить учебные службы и получить базовую линию — 15 минут

**Astra, отдельный терминал, без sudo**, каталог `$HOME/pr8`:

```bash
python3 tools/lab_services.py --bind "$ASTRA_IP" --variant "$N"
```

Оставьте терминал открытым. Он выводит три порта и сообщения запросов. Службы слушают только указанный IPv4, не весь компьютер. В другом терминале Astra задайте параметры шага 1 и выполните:

```bash
ss -lntup | tee results/sockets-before.txt
curl --noproxy '*' --max-time 3 "http://$ASTRA_IP:$PORT_A/"
curl --noproxy '*' --max-time 3 "http://$ASTRA_IP:$PORT_B/"
```

Ожидаются строки `PR8 variant=N service=A` и `service=B`. `ss` показывает оба TCP LISTEN и UDP-сокет. Порты выше 1024 не требуют root. Если порт занят, не меняйте номер порта самовольно: остановите только прежний собственный экземпляр службы или восстановите исходный снимок.

**Kali, без sudo для TCP/HTTP:**

```bash
nmap -n -Pn -sT --reason -p "$PORT_A,$PORT_B" "$ASTRA_IP" \
  -oN results/tcp-before.txt
curl --noproxy '*' --max-time 3 "http://$ASTRA_IP:$PORT_A/" > results/http-a-before.txt 2>&1
curl --noproxy '*' --max-time 3 "http://$ASTRA_IP:$PORT_B/" > results/http-b-before.txt 2>&1
python3 tools/udp_probe.py "$ASTRA_IP" "$PORT_UDP" > results/udp-app-before.txt 2>&1
sudo nmap -n -Pn -sU --reason --max-retries 1 -p "$PORT_UDP" "$ASTRA_IP" \
  -oN results/udp-before.txt
```

Проверки ограничены одним адресом Astra и тремя портами варианта; диапазоны подсети не сканируются. Nmap `-sU` посылает собственную пробу, на которую учебная UDP-служба может не отвечать, поэтому даже до фильтрации возможно `open|filtered`. **Критерий работоспособности UDP — ответ на `udp_probe.py`**, а не желаемая строка Nmap. Код выхода пробника: 0 — получен ответ, 2 — тайм-аут, 3 — сетевая ошибка.

**Условие перехода:** обе HTTP-службы и прикладной UDP-пробник отвечают с Kali. Если нет — сначала установите причину. Иначе последующее отсутствие ответа нельзя приписать новым правилам.

### Шаг 3. Составить и объяснить политику — 15 минут

**Astra, обычный пользователь**, каталог `$HOME/pr8`. Сначала составьте в отчёте матрицу разрешений своего варианта, затем сформируйте файл:

```bash
python3 tools/make_policy.py --variant "$N" --iface "$LAB_IF" \
  --astra "$ASTRA_IP" --kali "$KALI_IP" > policy.nft
cat policy.nft
```

Генератор только печатает текст; он не изменяет firewall. Прочитайте каждую строку. В отчёте объясните область действия таблицы `pr8_N`, hook `input`, условие интерфейса, источник/назначение, TCP-порт, состояние соединения, действие UDP и завершающий запрет. Укажите, какая HTTP-служба окажется недоступна и почему другие интерфейсы не получают эту учебную фильтрацию.

**Ожидание:** файл содержит только собственную таблицу и правила варианта. В нём нет общего сброса, NAT, перенаправления или доступа ко всем портам. Номер таблицы и порты должны совпадать с запущенными службами.

### Шаг 4. Проверить синтаксис и включить автоматический откат — 10 минут

**Astra, консоль гипервизора, административные команды через sudo:**

```bash
sudo nft list tables
sudo nft -c -f "$HOME/pr8/policy.nft"
```

Таблица `$TABLE` перед первым применением должна отсутствовать. Если она осталась от собственного предыдущего запуска, используйте шаг 7, проверьте базовую линию и повторите работу. Не удаляйте таблицы с неизвестным назначением. `-c` проверяет файл без применения; ожидается код 0 и отсутствие ошибок, но это ещё не проверка поведения.

До загрузки политики назначьте откат через 15 минут:

```bash
export NFT_BIN="$(command -v nft)"
sudo systemd-run --unit="pr8-rollback-$N" --on-active=15m \
  "$NFT_BIN" delete table inet "$TABLE"
systemctl list-timers --all "pr8-rollback-$N.timer"
```

Ожидание — таймер активен и имеет время срабатывания. Без рабочего таймера и консоли к применению не переходите. Затем:

```bash
sudo nft -f "$HOME/pr8/policy.nft"
sudo nft -a list table inet "$TABLE" | tee results/nft-after-load.txt
```

Фиксируйте фактический код возврата и вывод. Файл применяется одной транзакцией; не исполняйте отдельные строки вручную. При ошибке выясните причину и убедитесь, что таблица не появилась частично. Правила в этой работе **не включаются в автозагрузку**: `/etc/nftables.conf` и штатные службы не изменяются.

### Шаг 5. Повторить проверки с Kali — 15 минут

Повторите исходные команды с теми же параметрами и адресом, меняя имена файлов на `*-after`:

```bash
nmap -n -Pn -sT --reason -p "$PORT_A,$PORT_B" "$ASTRA_IP" \
  -oN results/tcp-after.txt
curl --noproxy '*' --max-time 3 "http://$ASTRA_IP:$PORT_A/" > results/http-a-after.txt 2>&1
curl --noproxy '*' --max-time 3 "http://$ASTRA_IP:$PORT_B/" > results/http-b-after.txt 2>&1
python3 tools/udp_probe.py "$ASTRA_IP" "$PORT_UDP" > results/udp-app-after.txt 2>&1
sudo nmap -n -Pn -sU --reason --max-retries 1 -p "$PORT_UDP" "$ASTRA_IP" \
  -oN results/udp-after.txt
```

Один HTTP-порт должен отвечать, второй — не отвечать с Kali; для запрещённого TCP обычно наблюдается `filtered` и тайм-аут curl. UDP-пробник отвечает только при разрешении UDP в варианте. Отрицательный результат не объявляется успехом, пока не подтверждены работающая служба и рост подходящего счётчика. Проверяйте новые запросы, не сохранённую страницу браузера и не старое соединение.

**Astra, сразу после запросов:**

```bash
ss -lntup | tee results/sockets-after.txt
sudo nft -a list table inet "$TABLE" | tee results/nft-after-tests.txt
```

Сопоставьте счётчики `allowed_http`, `variant_udp`, `deny_other_lab_input` до и после. В разрешённом случае увеличивается счётчик соответствующего разрешения, в запрещённом — счётчик отбрасывания. Несколько пакетов на один запрос нормальны. Фоновый трафик может увеличивать общий запрет, поэтому фиксируйте замеры непосредственно вокруг своего теста. Нулевой счётчик при отказе указывает, например, на другой интерфейс или более ранний штатный запрет.

### Шаг 6. Объяснить результат — 10 минут

Заполните таблицу своего эксперимента:

| Проверка | До | После | Служба слушает после? | Изменившийся счётчик | Вывод |
|---|---|---|---|---|---|
| HTTP A: Nmap и curl | | | | | |
| HTTP B: Nmap и curl | | | | | |
| UDP: прикладной пробник и Nmap | | | | | |

Дайте объяснения: почему запрещённая служба остаётся в `ss`; почему UDP `open|filtered` не доказывает успешный доступ; как отличить действие учебной политики от штатного firewall; что происходит с входящим IPv6 на внутреннем интерфейсе; почему изменение доступности трёх портов не означает устранения всех уязвимостей ОС.

Если счётчики и прикладные ответы противоречат ожиданию, опишите фактическое наблюдение и локализуйте причину. Подмена реального вывода ожидаемыми строками недопустима. Если таймер уже удалил таблицу, вернувшаяся доступность — результат отката: зафиксируйте это и повторите шаги 4–5 с заново назначенным таймером.

### Шаг 7. Восстановить исходное состояние — 10 минут

**Astra, консоль, sudo.** Сначала удалить собственную таблицу, затем остановить таймер, если он ещё ожидает:

```bash
sudo nft list tables
sudo nft delete table inet "$TABLE"
sudo systemctl stop "pr8-rollback-$N.timer"
sudo nft list ruleset > results/nft-restored.txt
```

Если таймер уже сработал, таблица отсутствует и повторное удаление сообщает об этом — это не основание удалять другие таблицы. При сообщении об отсутствии таймера проверьте журнал: `sudo journalctl -u "pr8-rollback-$N.service" --no-pager`. Для повторного опыта с тем же именем после завершения таймера при необходимости выполните `sudo systemctl reset-failed "pr8-rollback-$N.service"`; если transient unit ещё занят, используйте новый суффикс имени таймера и зафиксируйте его.

Пока учебные службы ещё запущены, на Kali повторите оба curl и UDP-пробник: все три должны отвечать, как до фильтрации. Сохраните результаты с суффиксом `restored`. Только после этого в терминале служб нажмите **Ctrl+C**. На Astra проверьте `ss -lntup`: учебные сокеты должны исчезнуть. Сравните правила с `nft-before.txt`: собственная таблица удалена; штатные правила сохранены. Изменение динамических счётчиков не является изменением самой политики.

Восстановление полного снимка допустимо при неисправности, но не заменяет доказательства управляемого удаления собственной таблицы и проверки связи. Не загружайте сохранённый полный ruleset поверх работающей системы как универсальную команду отмены.

<a id="troubleshooting"></a>
## 7. Диагностика затруднений

| Наблюдение | Проверка и действие |
|---|---|
| Пакет не находится | Проверить выпуск, архитектуру, штатные источники, результат `apt-get update`; использовать соответствующий ISO или комплект зависимостей |
| Нет сети для APT | Подготовить образ заранее либо применить раздел 3.3; не подключать внешний адаптер на этапе сканирования |
| `nft: command not found` | Установить `nftables`, открыть новый терминал/проверить `command -v nft`; путь в root-окружении может отличаться |
| `Operation not permitted` | Запустить через sudo на ВМ Astra; контейнер без сетевых capabilities не заменяет предусмотренную ВМ |
| `Address already in use` | Проверить `ss`, остановить прежний собственный процесс; не завершать неизвестные службы |
| `Cannot assign requested address` | Проверить, что ASTRA_IP действительно назначен Astra; сравнить с `ip -br address` |
| Нет ответа ещё до политики | Проверить маршрут, работающие службы, адрес, маску и штатные правила; не переходить к измерению эффекта firewall |
| Разрешённый HTTP не работает, счётчик равен 0 | Проверить фактический входной интерфейс, адреса, более ранние цепочки и управляющий firewall |
| Оба HTTP отвечают после применения | Проверить наличие своей таблицы, правильность интерфейса, срок таймера, новые запросы и параметр `--noproxy '*'` |
| UDP scan не меняется | Сопоставить прикладной UDP-ответ и счётчик; `open|filtered` допустим в обоих состояниях |
| `python3: can't open file` | Проверить `pwd`, наличие `tools` и путь; скрипты должны быть скопированы из комплекта |
| Ошибка повторного создания transient unit | Проверить старые timer/service, дождаться их завершения или использовать новое документированное имя; не отключать systemd |

## 8. Отчёт и доказательства

Отчёт должен включать титульный лист, название, цель и задачи; условие варианта; паспорт используемой части стенда; версию ОС и пакетов; последовательность действий; результаты; выводы и ответы на вопросы.

Обязательные доказательства:

1. Версии обеих ОС, адреса и маршруты только разрешённой сети; номер варианта.
2. Проверка наличия всех команд и описание выбранного способа установки. Для автономной установки — проверка контрольных сумм и зависимостей.
3. Исходные сокеты Astra, ответы двух HTTP и UDP-пробника с Kali, исходный scan.
4. Собственная матрица доступа и полный `policy.nft` с пояснением каждой строки.
5. Успешная проверка `nft -c`, действующий таймер и фактически загруженные правила.
6. Повторный scan, прикладные проверки, сохранённые сокеты и изменение счётчиков; заполненная сравнительная таблица.
7. Подтверждение удаления своей таблицы, восстановления всех трёх ответов и остановки учебных служб.
8. Вывод о том, какие возможности сохранены, какие ограничены и какими наблюдениями это доказано.

Приложите каталог `results` **с обеих ВМ раздельно**, `policy.nft` и использованные скрипты. Имена вроде `astra/results` и `kali/results` предотвращают перезапись одноимённых файлов. Снимки экрана должны содержать относящуюся к этапу команду и результат; ключевые текстовые выводы также сохраните файлами. Не включайте пароли, приватные ключи и другие секреты.

12. Почему сокращение видимой сетевой поверхности не заменяет обновление и настройку самих служб?

Критерии представлены в таблице 3.

**Таблица 3 — Критерии оценки по пятибалльной системе**

| Оценка | Критерии |
|---|---|
| **5** | Подготовка воспроизводима; исходная линия подтверждена; все разрешения и запреты варианта корректны; связь между правилами, ответами и счётчиками доказана; восстановление выполнено; отчёт полный, ограничения объяснены |
| **4** | Основная политика и восстановление верны; есть исходные и повторные прикладные проверки; отдельное неполное пояснение или второстепенный пробел в доказательствах не мешает подтвердить результат |
| **3** | Минимум подтверждён: одна HTTP-служба доступна, другая фильтруется при работающем слушателе; есть исходная линия и восстановление. UDP/счётчики или объяснения неполны; существенные замечания устранены с помощью преподавателя |
| **2** | Нет проверяемой исходной линии, политика не обеспечивает основное требование либо отсутствует подтверждение восстановления; результаты нельзя воспроизвести или выводы не подтверждаются материалами |

Оценка выставляется за результат и его доказательства, а не за число скриншотов. Невыполненная подготовка фиксируется как причина невозможности эксперимента; она не заменяется вымышленными результатами. Максимальная оценка и балл за работу — **5**.
